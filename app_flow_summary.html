BFAT v2 앱 전체 흐름 요약

이 문서는 현재 저장소의 활성 코드인 backend/와 frontend/를 기준으로 정리했습니다. _legacy/, BACKUP/, v1/은 이전 버전 또는 참고 코드로 보입니다.

FastAPI 백엔드 React + Vite 프론트엔드 Binance Futures REST/WebSocket SQLite 기본 DB 자동매매/실계좌 가능

1. 한 줄 요약

사용자가 로그인 후 대시보드에서 엔진을 시작하면, 백엔드가 Binance 15분봉 시장 스트림과 계정 주문 스트림을 연결하고, 전략 엔진이 캔들을 평가해 진입/청산 신호를 만들며, 리스크 계산과 상태머신 검증을 거쳐 Binance Futures 주문을 실행합니다. 결과와 상태는 DB, REST API, WebSocket을 통해 프론트 화면에 반영됩니다.

2. 최상위 흐름

1

로그인

/api/login으로 access token과 refresh cookie를 받습니다.

2

대시보드

REST로 지표를 조회하고 /ws/status로 상태를 실시간 수신합니다.

3

엔진 시작

/api/start가 EngineService.start()를 호출합니다.

4

시장/계정 스트림

15분봉 kline과 사용자 주문 체결 이벤트를 Binance WebSocket에서 받습니다.

5

주문/기록/표시

진입, SL, TP, 청산, 거래 로그, 수익률, 상태 진단이 화면에 표시됩니다.

3. 주요 폴더와 역할

백엔드

  • backend/main.py: FastAPI 앱 진입점, CORS, 라우터 등록, lifespan 초기화.
  • backend/services/engine_service.py: 엔진 생성, 시작/정지, Binance 스트림 관리, 상태 API 데이터 조립.
  • backend/app/core/engine/engine.py: BFAT 엔진 오케스트레이터. 전략, 리스크, 주문, 상태머신, DB 저장을 연결.
  • backend/api/*.py: 인증, 엔진 제어, 상태, 계좌, 로그 라우트.
  • backend/app/domain/: 포지션, 시그널, 상태머신, 전략 판단 도메인 모델.

프론트엔드

  • frontend/src/App.tsx: 인증 상태에 따라 로그인 페이지 또는 대시보드 표시.
  • frontend/src/context/AuthContext.tsx: 로그인, 토큰 갱신, 로그아웃 상태 관리.
  • frontend/src/components/Dashboard.tsx: 탭, 상태 WebSocket, 엔진 시작/정지, 주요 카드 렌더링.
  • frontend/src/components/InsightTab.tsx: 전략/시장 국면/진입 조건 표시.
  • frontend/src/components/TradesTab.tsx: 거래 이력과 성과 요약 표시.

4. 백엔드 시작 흐름

  1. Settings()가 backend/.env, 루트 .env, 현재 작업 디렉터리 .env 중 하나에서 설정을 읽습니다.
  2. DatabaseFactory.init_tables()가 migrations/의 SQL을 실행해 trade_log, equity_log, system_log 등을 준비합니다.
  3. BinanceAccountClient가 API 키 설정 여부를 확인합니다. 키가 없으면 계좌/주문 관련 API는 제한됩니다.
  4. EngineService가 앱 상태에 등록됩니다. 실제 BFAT 엔진은 사용자가 Start를 누를 때 생성됩니다.
  5. 종료 시 engine_service.stop()과 DB close가 호출됩니다.

5. 엔진 Start 후 자동매매 루프

엔진 구성

EngineService._build_engine()가 다음 의존성을 묶어 BFATEngine을 만듭니다.

  • StrategyEngine
  • RiskManager
  • KillSwitch
  • BinanceExecutionClient
  • StateMachine
  • 거래/자산/시스템 로그 저장소

시장 데이터

BinanceMarketStream은 시작 시 REST로 초기 15분봉을 가져오고, 이후 kline WebSocket을 구독합니다.

  • 닫힌 캔들: on_candle_close()
  • 진행 중 캔들: on_market_update()
  • Insight 갱신: 실시간/주기 REST 보정

계정 이벤트

BinanceUserStream은 listen key를 만들고 주문 체결 이벤트를 수신합니다.

  • reduceOnly 체결 감지
  • SL/TP/수동 청산 체결 반영
  • listen key keepalive

6. 전략 판단 흐름

StrategyEngine은 시장 국면을 먼저 분류한 뒤, 국면에 맞는 전략 하나만 활성화합니다.

국면사용 전략동작
TRENDING BreakoutStrategy EMA, ATR, 거래량, 방향성 조건을 바탕으로 추세 돌파 진입을 평가합니다.
RANGING RangeStrategy 범위 상단/하단/중앙, RSI, volume z-score를 이용하며 진행 중 캔들에서도 진입을 평가합니다.
국면 전환 Close-first 정책 포지션이 열려 있으면 새 진입보다 기존 포지션 청산을 먼저 요청합니다.

7. 주문과 리스크 흐름

진입

  • 신호 발생 시 상태머신이 FLAT -> ENTERING으로 이동합니다.
  • RiskManager는 기본 2.5% 리스크 기준으로 포지션 수량을 계산합니다.
  • Binance 시장가 주문이 체결되면 실제 체결가와 수량을 검증합니다.
  • SL과 TP 조건부 주문을 등록하고 확인한 뒤 OPEN 상태가 됩니다.

보호 주문

  • SL은 ATR 기반 가격이 잘못된 방향이면 실제 진입가 기준으로 재계산합니다.
  • TP는 현재 시장가 기준 즉시 발동 위험이 있으면 안전한 바깥 가격으로 repricing합니다.
  • SL/TP가 누락되면 재등록을 시도하고, SL 복구 실패는 포지션 flatten으로 이어질 수 있습니다.
  • 1R scale-out과 breakeven 이동 기능이 설정값으로 켜져 있습니다.

8. 상태머신

상태머신은 부작용 없이 포지션 수명주기만 검증합니다. 주문 실행과 DB 저장은 엔진 쪽에서 처리합니다.

FLAT -> ENTERING -> OPEN -> CLOSING -> FLAT

  • on_signal(): 신호 수신, 진입 대기.
  • on_entry_filled(): 실제 진입 체결 후 포지션 열림.
  • on_stop_update(): 손절가는 유리한 방향으로만 이동 가능.
  • on_exit_requested(), on_exit_filled(): 청산 처리 후 FLAT 복귀.
  • restore_position(): 앱 시작 시 Binance에 이미 열려 있는 포지션을 복원할 때 사용.

9. 프론트 화면 흐름

인증

  • 앱 로딩 시 /api/refresh로 기존 refresh cookie를 확인합니다.
  • 로그인 성공 시 access token을 메모리에 저장합니다.
  • 25분마다 access token을 갱신합니다.
  • API가 401을 반환하면 자동 refresh 후 재시도합니다.

대시보드

  • /ws/status?token=...으로 엔진 상태를 3초 간격 수신합니다.
  • /api/insight는 15초 또는 60초 주기로 탭별 조회됩니다.
  • /api/equity는 30초마다 계좌 equity fallback을 조회합니다.
  • 탭: Dashboard, Insight, Trades, Logs, Chart.

10. 주요 API

MethodPath역할
POST/api/login관리자 로그인, access/refresh token 발급.
POST/api/refreshrefresh cookie로 access token 재발급.
POST/api/start엔진 백그라운드 실행 시작.
POST/api/stop엔진과 스트림 정지.
GET/api/status엔진 상태, 포지션, SL/TP, PnL, 진단 정보.
GET/api/insight시장 국면, 전략 판단 근거, 진입 조건.
GET/api/trades닫힌 거래 이력.
GET/api/trades/summary승률, 평균 R, 기대값, 순손익, MDD.
GET/api/logsDB에 저장된 시스템 로그.
WS/ws/status대시보드 실시간 상태 스트림.

11. 데이터 저장 흐름

  • trade_log: 진입/청산 가격, 수량, PnL, R multiple, 초기 손절가, trade hash, 검증 상태.
  • equity_log: 시점별 equity 기록.
  • system_log: 엔진 시작/정지, 주문 복구, 오류, R 검증 문제 등 운영 로그.

거래가 닫히면 BFATEngine.on_position_closed()가 R multiple을 계산하고, kill switch를 갱신한 뒤 DB에 저장합니다.

12. 운영상 주의점

  • BINANCE_TESTNET=false이면 실제 선물 계좌 주문이 나갈 수 있습니다.
  • APP_USERNAME, APP_PASSWORD, JWT_SECRET, Binance API 키는 반드시 .env에서 설정해야 합니다.
  • README/SETUP과 일부 프론트 문구에 문자 인코딩이 깨진 흔적이 있습니다. 기능 흐름과 별개로 사용자 화면 문구 정리는 필요해 보입니다.
  • Chart 탭은 TradingView 외부 스크립트를 로드하므로 네트워크 또는 CSP 환경에 영향을 받습니다.
  • 엔진은 스트림 재연결과 SL/TP 복구 로직을 갖고 있지만, 자동매매 앱 특성상 실계좌 전에는 testnet과 소액 검증이 필수입니다.

13. 빠른 실행 기준

백엔드: ./start_backend.sh 또는 cd backend && uvicorn main:app --host 0.0.0.0 --port 8000

프론트엔드: cd frontend && npm install && npm run dev

개발 서버 기준 포트는 백엔드 8000, 프론트엔드 5173입니다.

14. 이번 수정 반영 사항

TP/SL 주문 안정화

  • 시장가 주문에 newOrderRespType=RESULT를 추가해 엔진이 기대하는 FILLED, executedQty, avgPrice 응답을 받도록 했습니다.
  • SL/TP 조건부 주문은 기존 /fapi/v1/algoOrder 실패 시 /fapi/v1/order의 STOP_MARKET, TAKE_PROFIT_MARKET으로 fallback합니다.
  • 청산/flatten 주문은 반대 방향 일반 시장가가 아니라 reduceOnly 시장가로 실행합니다.
  • 신호에 TP가 없어도 엔진이 ATR 기반 TP를 반드시 생성합니다. TP 등록 실패 시 포지션을 유지하지 않고 fail-closed 처리합니다.

전략/리스크 파라미터 명확화

  • backend/app/config/constants.py에 전략/리스크 상수를 모았습니다.
  • 기본 리스크는 거래당 1%로 낮췄습니다.
  • 추세 전략은 EMA 12/50, ATR 14, SL 1.8 ATR, TP 3.6 ATR 기준입니다.
  • Range 전략은 범위 바깥 손절 buffer를 max(가격의 0.6%, 0.7 ATR)로 계산하고, 최소 보상/위험 비율은 1.10으로 올렸습니다.
